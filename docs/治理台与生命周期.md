### 1.0.1 为什么这条链路之前一直失败（已结案）

```text
现象：/guard/api/config → 404，而 CORS、四个 hook、独立治理台全部正常
排除：不是时序（callbackFired/serviceSeen 都 True）、不是权限、不是前缀冲突
真因：register 被当成普通函数调用，this 丢失 → this.exact 读不到 → TypeError
教训：测试替身必须复刻真机的 this 依赖，否则这类缺陷在单测里完全不可见
      （旧替身的 register 不依赖 this，所以一路绿灯）
```

验证方式（同语义替身，离线可跑）：`node zz-probe-live/check.mjs` 形式的脚本 —— 用
`register(route) { const t = route.kind === "exact" ? this.exact : this.prefixes; … }` 的替身调用真实
dist，得到 `prefixes: ["/guard"]` 且 `registered: true`。

## 1.1 为什么必须重启 DSH

安装 bundle 时 profile 通过 HMR 重组了配置（行已生效，四个 hook 已挂上，治理台已监听 8787），
但 **HMR 只重组配置，不会重新加载已装载模块的新一代 JavaScript**（`dsh-hmr` 源码：`import()` 新代
之前清缓存，但只对"被接受的文件变更"触发，且忽略 `node_modules`）。因此：

- 现在进程里跑的是**首轮装载的旧代码**：没有 loopback CORS、也没有 `ctx.inject` 等待；
- 浏览器打开 `http://127.0.0.1:8787/` 可用（同源，不需要 CORS）；
- Web GUI 面板能点开、能看到图标，但会因为跨源被拦而显示"尚未连接"；
- 重启 DeepSeek Harness 后，上面两条 ⚠️ 会自动变成 ✅（代码已就绪且有测试守护）。

重启后的自检（三条都应通过）：

```powershell
# ① 同源路由就绪
Invoke-WebRequest http://127.0.0.1:19387/guard/api/config -UseBasicParsing | Select-Object StatusCode
# ② 独立端口 + CORS（Origin 为 loopback 时应回显）
(Invoke-WebRequest http://127.0.0.1:8787/api/snapshot -UseBasicParsing -Headers @{Origin='http://127.0.0.1:19387'}).Headers['Access-Control-Allow-Origin']
# ③ 面板入口仍注册
#    用 cordis_inspect_query: platform=client provider=Slots method=listSubTree root=sidebar.panellist
#    期望 occupants 里同时有 plugins 与 guard
```

## 3. 怎么手动验证一次完整生命周期

### 3.1 审批放行链路（沙箱升级请求）

1. 在 GUI 里把会话权限档位设成 **workspace-write**（默认），审批策略保持 **ask**；
2. 让 Agent 执行一次越出工作区的写入（模型会带 `sandbox_permissions: danger-full-access` + `justification` 重试）；
3. 弹出审批 → 批准一次；
4. 打开 http://127.0.0.1:8787/ ，「授权与剩余时间」里应出现一条 `kind=universal`、
   scope 为这条操作的授权（工具 + 参数 + 目标档位），倒计时实时递减；
5. 让 Agent 再执行**同一条**操作（`justification` 措辞可以不同；换命令 / 换路径 / 换目标档位不算）→ 不再弹审批；
6. 等 TTL 到期（产品默认 30 分钟，可在 tab 里调整）后再执行同一条操作 → 重新询问；
   审计里是 `LEASE_ISSUED` → `LEASE_REUSED` → 到期后重新 `ASK`。

> Guard **不会修改会话沙箱档位**：第 4 步页面上的「沙箱档位」只是宿主读数，批准不会把会话变成可写。
> 第 5 步不再弹审批，是因为 Guard 在 `approval/request` 上代答了 `allowed-once`，DSH 仍按单次升级执行。
>
> 如果第 5 步仍然弹审批：多半是操作指纹不一致（参数或目标档位变了），或没有在 `tools/execute` 记录到这次调用；
> 此时是**失败即回落原生审批**，不会越权。

### 3.2 审批策略必须是 ask

`approval policy = never` 时，DSH 在瀑布派发**之前**就把审批判成 `rejected`，Guard 根本收不到事件，
不会有任何授权签发。这是设计使然（Guard 不绕过 Approval），不是缺陷。

## 4. 出问题看哪里

| 现象 | 排查 |
|---|---|
| 治理页面打不开 | 端口是否被占用（stderr 打印的 `[dsh-guard] governance console: …`）；`console.enabled` 是否为 false |
| 面板显示「尚未连接到治理接口」 | 同源 `/guard/` 与 8787 起 4 个端口都没响应；先确认独立页面能打开，再看浏览器控制台的 CORS/404 |
| 审计里只有 `PASSTHROUGH_ALLOW` | 正常：standard profile 的 `tools/pre-execute` 落底就是 allow；只有沙箱升级会产生 ASK→LEASE |
| 改了代码没生效 | 见 2.2：HMR 不换 JS 代，必须重启 |

## 5. 安全边界（不要越界实现）

- **策略写接口**只能改 `defaultScope` / `defaultTtlSeconds` / `maxTtlSeconds`；
  `enabled` 与 `rules` 永远返回 400（页面不能关掉 Guard，也不能凭空造授权规则）。
- **收缩型动作**（`POST /api/revoke`）只有一个动作 `revoke`：撤销该会话全部有效授权并写 `LEASE_REVOKED`。
  不得扩展成任何授予/放宽入口（放宽只有用户显式开启的免打扰窗口 `/api/dnd`）。
- `tool` 挡位禁止作为默认值（规格第 7 条），接口层与 UI 下拉都禁用它。
- 运行时改动**不落盘**：不擅自改写 profile 的 `cordis.patch.yml`（那是用户与 DSH 插件管理器的地盘），
  重启后回到 profile 配置值。
- 面板不做任何审批 / 签发动作（审批必须走 DSH 原生；页面只提供收缩）。

## 6. 授权状态 vs 宿主档位读数（2026-11-01 收敛）

> **入口分两层，都在会话里**（2026-10-31 按所有者要求：先不做全局中台）：
> ① **模式 chip**——输入框工具栏（`conversation.input.left`），常驻显示当前授权模式与免打扰倒计时；
> ② **详情层**——会话内「能力授权」tab（`conversation.view`，排在 对话 / 轨迹 之后，order 20），
> 整页展示每条授权、到期后果、技术详情、设置与本会话最近记录。
> 两个槽位都是 session 作用域、组件直接拿到 `sessionId`，因此显示的一定是当前会话。
> 原先的全局面板（`main`）与侧栏图标（`sidebar.panellist`）已移除；独立页面 `8787` 仅作排障。

治理台首屏把两件事**分开显示**，不再用一个倒计时概括一切：

| 状态 | 数据来源 | 页面表现 |
|---|---|---|
| 授权是否仍有效 | `LeaseManager`（实时 `Date.now()` 比较） | 「生效中 / 即将到期 / 已到期 / 已撤销」+ 倒计时 |
| 当前沙箱档位 | 宿主实时读数（`currentMode`） | 只显示「只读 / 工作区可写 / 完全访问 / 未知」 |

关键规则（实现与测试都以此为据）：

1. **倒计时归零只代表授权到期**。档位是宿主读数，与倒计时无关。
2. **Guard 从不改写档位**：2026-11-01 起「提升 + 回滚」链路已删除，因此不存在「待回滚 / 已恢复 / 由你设定」这些状态。
3. **读不到宿主档位 = `未知`**，不允许推测。
4. 免打扰窗口是**独立状态**（`sessions[].dnd`），不是授权、也不是档位；它的到期/结束只影响「要不要放行审批」。
5. 低频结算由 `sweepIntervalMs`（默认 30s）驱动，只用于及时更新免打扰窗口状态与审计；关掉它不影响任何安全判定。
