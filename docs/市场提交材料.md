# 插件市场提交材料

本文件是提交各 DSH 插件市场时可直接复制的文案与步骤。发布流程细节见 [`发布与收录.md`](./发布与收录.md)。

## 0. 发布前置（账号操作）

1. 登录 npm 官方 registry：`npm login --registry=https://registry.npmjs.org`。
2. 创建 `@dsh-capsule` 组织：<https://www.npmjs.com/org/create>（当前 npm 上该 scope 不存在；组织名被占用时必须改用备选包名）。
3. 备选包名（均已确认未被占用）：
   - `dsh-capability-guard`（无 scope，发布最简单；需同步修改 `adapter/package.json`、`adapter/cordis.patch.yml`、`adapter/client.js` 的模块 id 与 README 安装命令）；
   - `@<你的 npm 用户名>/dsh-capsule`（个人 scope，无需组织）。
4. GitHub 仓库 Settings → Topics 与 About → Description 按第 3 节填写。

> 命名冲突提示：GitHub 上已有 `2-c-q/dsh-capsule`（Linux Bubblewrap 隔离项目），dshbase 的 `/plugins/dsh-capsule/` 已指向它。提交 dshbase 时务必注明 `whDonline/dsh-capsule`；市场可能给条目加后缀（如 `dsh-capsule-2`）。npm 包名 `@dsh-capsule/adapter` 与之无冲突。

## 1. 基本信息

| 字段 | 值 |
| --- | --- |
| 插件名 | DSH Capsule（Capability Guard） |
| npm 包 | `@dsh-capsule/adapter` |
| 仓库 | <https://github.com/whDonline/dsh-capsule> |
| 许可证 | MIT |
| 安装命令 | `dsh plugin --profile web add @dsh-capsule/adapter` |
| 支持 DSH | `>=0.1.5-0 <0.3.0`（`engines.dsh`） |
| 平台 | Web（Windows / macOS / Linux） |
| 运行时依赖 | 无（宿主接口通过 Cordis 注入） |

### 中文简介（100 字内）

> 把重复审批变成有期限、可撤销、可追溯的短期授权。为 DSH 原生审批增加 Lease 复用、免打扰窗口、敏感路径保护与本地授权决策记录；不改写沙箱档位，不改审批策略。

### 英文简介

> Turn repeated approvals into time-limited, revocable, auditable grants. DSH Capsule adds short-lived leases, do-not-disturb windows, sensitive-path protection and local authorization decisions to native DSH approvals — without rewriting sandbox modes or approval policy.

### 分类与标签

- 分类：权限与审批（security / permissions / developer tools）
- 标签：`dsh`、`dsh-plugin`、`deepseek-harness`、`cordis-plugin`、`approval`、`authorization`、`permissions`、`sandbox`

## 2. dsh.so 提交

入口：<https://www.dsh.so/submit/>

1. 在输入框粘贴仓库地址 `github.com/whDonline/dsh-capsule`（或 npm 包 `@dsh-capsule/adapter`），点 **Run checks**。
2. 选择 **dsh plugin** 类型。
3. 检查通过后点 **Submit to dsh.so**；服务端会重新抓取并扫描，随后进入后台 issue 审核。
4. 审核合并后在插件页确认：L1（仓库/README）、L2（manifest 完整）、L3（安装命令与 DSH 版本要求）应通过；L4 / L5 由 dsh.so 的沙箱自动跑。

若安全扫描出现 warning（本插件会读写文件、注册审批钩子，属功能必需），在审核 issue 中说明：

> Capability Guard 本身不执行用户命令；它观察 DSH 的工具与审批事件，注册一个单调拒绝的 `tools.guard()`，并把授权/审计写到本机。`families.ts` 里的 `rm` / `Remove-Item` 等字符串是「识别破坏性命令、禁止其通过操作族复用」的排除表，不是执行路径。

## 3. GitHub 仓库设置（需仓库所有者操作）

仓库页 → **Settings** → **Topics**：

```text
dsh-plugin
dsh
deepseek-harness
cordis-plugin
typescript
```

仓库页顶部 **About** → Description：

```text
Short-lived authorization leases, do-not-disturb windows and local authorization decisions for DeepSeek Harness.
```

`dsh-plugin` topic 是 DSH-Plugins-Marketplace 等自动索引的入口；加完后约 2 小时内会被扫描收录，无需申请。

## 4. awesome-dsh-plugin

仓库：<https://github.com/awesome-dsh-plugin/awesome-dsh-plugin>

在对应的分类（权限 / 安全 / 开发工具）中添加一行，格式沿用相邻条目：

```markdown
- [dsh-capsule](https://github.com/whDonline/dsh-capsule) - Short-lived authorization leases, do-not-disturb windows and local authorization decisions for DSH approvals.
```

提 PR 前先跑一次 `git clone` + `pnpm install --frozen-lockfile && pnpm build && pnpm test`，在 PR 描述里写明验证结果与 DSH 版本。

## 5. dshbase.com

目录：<https://dshbase.com/plugins/directory/>

dshbase 的数据源是 GitHub `dsh-plugin` topic 与 dsh.so catalog 的合并结果。加完 topic 后若 24 小时内仍未收录，用提交模板：

<https://github.com/ylwl1997/dshbase/issues/new?template=plugin-submission.yml>

在 issue 中写明仓库是 `whDonline/dsh-capsule`（避免与已有的 `2-c-q/dsh-capsule` 混淆），并附一句：

> DSH Capsule: short-lived authorization leases and do-not-disturb approval windows for DSH, MIT, dsh.bundle declared, `dsh plugin add @dsh-capsule/adapter`.

## 6. 发布后自检

- `npm view @dsh-capsule/adapter version` 返回已发布版本；
- 在一个全新 profile 中执行安装命令，`dsh --profile <name> --dump-config` 能看到 `capability-guard` 层；
- DSH Web 启动后输入框左侧出现 Guard 模式 chip，会话内第三个 tab「能力授权」可打开；
- dsh.so 插件页的安装命令与本仓库 README 一致。
